# ไข่หวานช่วยด้วย (kaiwan_chuaiduai)

ต้นแบบ (prototype) แอปขอคำปรึกษาพี่ไข่หวาน — เก็บข้อมูลในฐานข้อมูล SQLite บนเครื่อง (ไม่มี server)

- ปิดแอปแล้วข้อมูลยังอยู่ และจำการล็อกอินไว้จนกว่าจะกดออกจากระบบ
- รหัสผ่านเก็บเป็น hash (sha256) ไม่เก็บตัวจริง
- เปิดครั้งแรกเริ่มจากข้อมูลว่างเหมือนของจริง มีแค่บัญชีเจ้าหน้าที่ 3 คน + นักศึกษาทดสอบ 1 บัญชี (ไม่มีแชท/นัดตัวอย่าง)
- รีเซ็ตข้อมูล (ล้างทุกอย่างแล้วกลับเป็นข้อมูลตั้งต้น): `flutter run --dart-define=RESET_DB=true`
  (ล้างทุกครั้งที่รันด้วยคำสั่งนี้ รันปกติใช้ `flutter run` หรือกด Run ใน VS Code)
- ข้อจำกัด: ข้อมูลอยู่เฉพาะเครื่องนี้ แชทข้ามเครื่องต้องมี server ภายหลัง

## ติดตั้งและรัน (เครื่องที่ยังไม่ได้ตั้งค่า)

1. `flutter pub get`
2. `flutter run` — **รันได้ทันที** ไม่ต้องตั้งค่าอะไรเพิ่ม

  (รูปแบบดูที่ `assets/config/staff_accounts.sample.json`)
  ถ้าไม่มีไฟล์นี้ แอปใช้บัญชีตัวอย่าง staff1–3@nu.ac.th / changeme1–3 แทน

## Flow

- **นักศึกษา**: เลือกหัวข้อ 2 แบบ
  - **ถาม/ตอบเรื่องทั่วไป** → เลือกช่องทาง
    - **ที่ห้องกิจการนิสิต** → "เจ้าหน้าที่คนไหนก็ได้" (แจ้งเตือนทุกคน) หรือ "เลือกเฉพาะเจาะจง" → เลือกพี่ (แจ้งเตือนเฉพาะคนนั้น)
      → เลือกวันในปฏิทิน + เวลาจาก dropdown (ครั้งละ 30 นาที เลือกได้ทุกช่อง) → ส่งคำขอ → รอเจ้าหน้าที่ยืนยัน (ดูสถานะที่แท็บ "นัดหมาย")
      ถ้าพี่เสนอเวลาใหม่ กด "ตกลงเวลานี้" หรือ "เลือกเวลาอื่น"
    - **ผ่านแอป** → "เจ้าหน้าที่คนไหนก็ได้" (เข้าแชททันที) หรือ "เลือกเฉพาะเจาะจง" → เลือกพี่ไข่หวาน → แชท
  - **ขอความช่วยเหลือแบบเร่งด่วน** → เข้าแชททันที ส่งถึงเจ้าหน้าที่ทุกคน (แสดงเป็นสีแดง)
- **เจ้าหน้าที่**:
  - หน้าแรก: ตัวเลขสรุป + **ประวัติการปรึกษา** แยกหัวข้อ (ทั่วไป / เร่งด่วน) = แชทที่จบแล้วพร้อมสรุป (นัดหมายดูที่แท็บ "นัดหมาย")
  - แท็บ "ข้อความ": แชทที่ยังคุยอยู่ เรียงลงมา (เร่งด่วนที่ยังไม่อ่านขึ้นบนสุด) กรอง ทั้งหมด / ส่วนรวม / ส่วนตัว
  - **จบการปรึกษา** (เมนู … ในแชท): ต้องกรอก "เรื่องที่ปรึกษา" และ "คำปรึกษาที่เจ้าหน้าที่ให้"
    ถ้านักศึกษากดจบเอง เจ้าหน้าที่กด "บันทึกสรุป" ทีหลังได้
  - **ตารางสรุปเคส** (การ์ดในหน้าภาพรวม): เคสของฉันเรียงตามวันที่ กรองรายเดือน/กำหนดช่วงวันเอง และ ทั้งหมด/online/onsite
    - แถว online มาจากแชทที่จบแล้วอัตโนมัติ, แถว onsite กด "เพิ่มเคส onsite" เอง
    - แตะแถวเพื่อแก้ ประเภท/เรื่องที่ปรึกษา/คำปรึกษา/ระดับ (แก้เฉพาะในรายงาน ไม่กระทบแชท)
    - export (ปุ่มแชร์มุมขวาบน): CSV, PDF
  - แท็บ "นัดหมาย": คำขอนัดจากนักศึกษา เจ้าหน้าที่ตรวจเวลาว่างเอง แล้วกด "ยืนยัน สะดวกเวลานี้"
    หรือ "เสนอเวลาอื่น" (เลือกวัน/เวลาที่ตัวเองว่าง + ข้อความ) · ถ้าเวลานั้นมีนัดที่ยืนยันแล้วจะมีคำเตือน ⚠
- ข้อความที่นักศึกษาส่งแบบเจาะจงจะไปถึงเฉพาะเจ้าหน้าที่คนนั้น

## โครงสร้าง

- `lib/data/` — models, `AppData` (ข้อมูลกลาง + ค่าคงที่ + ข้อมูลตั้งต้น), `app_database.dart` (SQLite), `registration_rules.dart`, `passwords.dart`, `report_export.dart` (CSV/PDF)
- `lib/providers/` — state management ด้วย **Provider** (บทที่ 10–11) แยกตามฟีเจอร์
  - `auth_provider.dart` ล็อกอิน / สมัคร / โปรไฟล์
  - `chat_provider.dart` แชท / ไฟล์แนบ / จบการสนทนา
  - `appointment_provider.dart` นัดหมายห้องกิจการนิสิต
  - `report_provider.dart` ตารางสรุปเคส
  - `app_providers.dart` รวมทุกตัวด้วย `MultiProvider` + `ChangeNotifierProxyProvider` (Chat/Appointment/Report พึ่ง Auth, Chat พึ่ง Report)
  - หน้าจอใช้ `context.watch<...>()` ใน build (วาดใหม่เมื่อข้อมูลเปลี่ยน) และ `context.read<...>()` ในปุ่ม/คำสั่ง
- `assets/fonts/` — ฟอนต์ Sarabun (OFL) ใช้วาดตารางใน PDF
- `lib/screens/` — หน้าจอ
  - `auth_screens.dart` login / สมัคร / หน้าขอความยินยอม · `student_screens.dart` · `staff_screens.dart` · `profile_screen.dart` · `report_screen.dart`
  - `chat/` หน้าแชท: `chat_screen.dart` (หน้าหลัก), `message_bubble.dart`, `attachments_view.dart` (รูป/ไฟล์แนบ), `emergency_card.dart` (เบอร์ฉุกเฉิน), `composer.dart` (ช่องพิมพ์), `summary_sheet.dart` (สรุปตอนจบแชท)
  - `appointment/` นัดหมาย: `booking_screen.dart` (จองนัด), `my_appointments.dart` (นิสิต), `staff_appointments.dart` (เจ้าหน้าที่ + เสนอเวลาใหม่), `appointment_card.dart` (การ์ดนัด + ป้ายสถานะ)
- `lib/widgets/common.dart` — การ์ดเมนู (`MenuCard`), รูปโปรไฟล์, ป้ายกราฟิก, แผงเหลืองขอบโค้ง, กันออกจากฟอร์มที่กรอกค้าง (PopScope)
